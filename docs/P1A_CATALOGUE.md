## 重复导入的规则

| 情况 | 行为 |
| --- | --- |
| 同项目、同规范路径、文件未变、请求的分析已完成 | 直接复用；clip_id/event_id、事件集合和记录数不变；不重复写入分析步骤、不探测/抽帧/调用模型 |
| 相对/绝对路径、可解析路径别名指向同一文件 | 归一为同一素材；不简单对所有路径转小写 |
| 属性改变但已有 hash 能确认内容相同 | 更新指纹，保留来源版本与既有分析 |
| 内容改变 | 保留 clip_id，递增 source_revision；发布新版本的实际分析结果，旧事件保留为历史但退出当前检索 |
| 同一窗口重新标注 | 保留 event_id；不把模型/提示词更新当作新窗口 |
| 事件标签或 embedding 缺失 | 只补缺失部分；已有窗口和有效观察保留 |
| 导入其他文件夹 | 追加/更新，不覆盖前一个文件夹的目录 |
| 显式 synchronize | 完整、非空且无错误的扫描后，仅将该根目录内缺失素材标为离线，不删除历史 |
| 扫描失败、目录离线、空目录、扫描超限 | 保留已有目录；不将不完整扫描当成全项目删除指令 |

默认以 size + mtime_ns 做快速判断。新文件或属性变化时计算内容 hash；未变文件不重复全文件哈希。`verify_content=True` 可对保留相同大小与时间戳的替换做严格检查。legacy 没有历史 hash 时，无法仅凭新算出的 hash 反推过去的文件内容；对指纹未变的 legacy 文件可先做一次严格校验建立 hash 基线而复用分析。

真正新增文件、新内容版本或新窗口会合理分配新 ID；重复导入相同视频不会让有效素材/事件记录随点击次数增长。历史事件数量可能随真实内容或分段变化增加，读取接口只返回当前有效集合。

## 一致性与失败恢复

- 媒体处理在事务外；一个文件的元数据、事件集合切换、事件内容与分析状态在一个短事务内发布。
- 来源版本变化用预期版本检查，拒绝将过期结果写回新来源。
- 事务失败会回滚元数据、事件与状态；失败的重新分析不清除仍有效的既有观察。
- 新来源无法完成探测时不覆盖旧结果；不可验证的变更/离线来源退出当前检索。未变且仍可验证的来源遇到一次重新分析失败，不会无故下线。
- 当前单进程 UI 中同一项目的并发导入串行复查缓存，防止重复分析；跨进程 durable worker/租约仍属于 P2。
- 事件集合内 order 和规范时间范围唯一；事件父关联包含项目与素材，跨项目挂接由数据库拒绝。
- 迁移先预检路径冲突、父子关系、范围与支持的字段，再备份和开启事务。发现冲突会报告，不静默合并/丢弃。测试可注入发布故障验证回退。

## 旧调用方与时间线

运行 SQL 已切换新表与字段。为让 P1a 独立可用，公开的 `get_catalogued_shots` / `replace_project_shots` 暂时作为新实现的函数别名，读取边界提供 `shot_id=clip_id`。没有保留两套数据，也不再执行旧的全项目替换。它们在 P1b 连同 Pydantic/状态/工具提示一并清理。

新时间线片段携带 clip_id、source_revision 和适用的 event_set_id。导出前检查来源版本、真实 ID/路径对应、有效事件及当前磁盘指纹。旧计划若缺少来源版本，要求重新生成；不会把当前同路径文件自动认作历史内容。导出 JSON/公开契约的完整版本化读入仍在 P1b。

## 部署和回退

新空目录首次启动直接创建 v1。旧库要求显式部署，应用导入不会趁代码热重载时自行迁移生产数据：

```powershell
python -m scripts.migrate_catalogue app/data/mapo_catalogue.db
```

本工作区已执行此命令。若 UI 仍在运行，应重启应用，让现有进程加载新代码与数据库结构。

迁移前停应用并保留备份；恢复时同样停 UI/worker，在新目录用配套的旧代码与备份验证后再切换。不要把旧代码直接指向 v1，也不要在数据库打开时覆盖 `.db` 或混入旧 WAL/SHM。

## 验证结果

- 自动回归：58 项通过，3 项严格预期失败；后者是 P1b 候选白名单与 P5 的两项 FPS 问题。
- 完整目录副本：105 条 clips、450 条 clip_events、105 个 event_sets、420 条 legacy analysis_steps，两个项目各重复导入三次，所有 ID 集合及记录数不变。
- 完整目录副本的探测、解码、视觉、embedding、hash 和网络操作均被阻断，验收仍全部复用成功；只进行必要的扫描和 stat。
- 模拟媒体测试覆盖部分事件失败补齐、只补 embedding、强制重新标注、同大小/mtime 替换、追加和范围同步、并发重复导入、事务回滚、旧计划拒绝及磁盘变更。
- 迁移演练核对全量历史行及 embedding，并验证重复启动、路径冲突拒绝、外键约束和故障回退。
- 没有重分析真实视频，没有调用付费模型。
- 复验修正 P0 备份清单对临时 WAL/SHM 的依赖：新快照转为 DELETE journal 的单文件格式；旧清单仅忽略临时 SHM 和已记录为空的 WAL，出现非空 WAL 则拒绝校验，主数据库与导出文件仍逐一核对 SHA-256。
