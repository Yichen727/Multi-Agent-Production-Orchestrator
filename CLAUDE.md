# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MAPO (Multi-Agent Production Orchestrator) is a LangGraph multi-agent system for film/video post-production workflows. An MSc project (UCL CGVI). **Four** specialised ReAct agents form a strict linear pipeline — **Ingest → Search → Selection → Delivery** — coordinated by a supervisor and exposed through a Streamlit UI. The metadata database is SQLite, **persisted to a file** (`settings.METADATA_DB_PATH`) so real ingested rows survive app restarts (the demo catalogue is seeded only when the DB is empty, and is replaced by real data when the user runs ingest): ingestion genuinely probes each file with ffprobe (dimensions, orientation, fps, codec, audio, duration), runs FFmpeg scene-cut detection, and sends sampled frames to **GPT-4o Vision** for tagging (shot type, objects, keywords, description, approximate people count). Whisper transcription and face/speaker *identity* recognition are intentionally **not** implemented. The guiding rule everywhere: **store only what a tool measured or the vision model actually saw; leave the rest `unclassified`; never fabricate** (PostgreSQL remains the aspirational production datastore).

The system is a clean AI-assisted editing pipeline — **Ingest builds the semantic knowledge base, Search retrieves candidates via hybrid recall, the editor curates which clips participate (a UI Human-in-the-Loop layer), Selection orchestrates those curated clips into a narrative edit timeline, and Delivery compiles that timeline into a Premiere Pro–importable project file.** It was refactored from an earlier 6-agent design, then a 4-agent two-phase design: the Metadata Agent was renamed to the **Ingest Agent**, and the **Quality Agent was removed entirely** (quality is now the editor's judgement, informed by the Selection Agent's reasoning — there is no automated scoring agent). The **Delivery Agent** was then (re)introduced as the 4th, final stage: a pure project compiler (no creative editing/ranking). Of the earlier removed modules only `delivery_agent` came back; the rest stay deleted, and a test asserts they are no longer importable.

## Commands

```bash
pip install -r requirements.txt    # install deps
python main.py                     # launch — the ONLY supported entry point (spawns streamlit)
streamlit run app/ui/streamlit_app.py   # equivalent direct launch

pytest tests/ -v                   # run all tests
pytest tests/test_agents.py::test_shot_query -v   # run a single test
```

Requires an `OPENAI_API_KEY` in `.env` (already present in this workspace). FFmpeg/ffprobe must be on PATH for ingest proxy/frame tooling to work — if absent, those tools return graceful error strings rather than crashing.

## Architecture

The system is assembled in [app/orchestrator/production_orchestrator.py](app/orchestrator/production_orchestrator.py) — read this first; it's the spine that ties everything together.

**Three layers:**

1. **Top-level graph (`mapo_agent`)** — a `StateGraph` with two human-in-the-loop (HITL) gates around the supervisor:
   `START → verify_project (HITL gate 1) → supervisor → [conditional] human_approval_gate (HITL gate 2) → END`.
   The HITL gates use LangGraph `interrupt()`. The approval gate only fires when `state["selected_shots"]` or `state["recommendations"]` is non-empty. **Note:** the current agents populate state only via `messages` (not these fields), so in practice the gate is inert; and the Streamlit UI calls `mapo_agent.invoke(...)` directly without resume-after-interrupt, so any `interrupt()` surfaces as an interruption rather than a re-prompt loop — keep both facts in mind when changing gate logic.

2. **Supervisor** — built with `langgraph_supervisor.create_supervisor` over the four compiled sub-agents. It routes by intent (prompt in `SUPERVISOR_PROMPT`) and does no work itself. `output_mode="last_message"`. The strict pipeline order (Search/Selection/Delivery only after Ingest) is enforced by the **UI**, which locks the later phases until Ingest completes.

3. **Four sub-agents** in [app/agents/](app/agents/), each a self-contained ReAct loop (`assistant → tools → assistant`) compiled by the `_build_agent_graph` helper. The pipeline is linear: `ingest_agent` → `search_agent` → `selection_agent` → `delivery_agent`.

### The four agents

Each agent is **self-contained**: it defines its own `@tool` functions, the `<name>_tools` list, the assistant node, and the router. There are exactly four agent modules — the earlier `metadata_agent`/`quality_agent`/`shottagger_agent`/`gradebot`/`selectbot` modules were renamed/removed and **deleted** (one source of truth, no fallback path). A test asserts those modules are no longer importable. (`delivery_agent` was later re-added as the 4th stage and now imports cleanly.)

| Agent ([file]) | Responsibility | Owns tools |
|---|---|---|
| [ingest_agent.py](app/agents/ingest_agent.py) | Scan, probe, vision-tag, **embed**, catalogue (SQLite + JSON) — builds the searchable semantic knowledge base | `detect_new_footage`, `ingest_footage` (full pipeline: ffprobe metadata + scene-cut detection + GPT-4o Vision tagging incl. semantic dims `camera_motion/lighting/mood/subject_position` + a semantic embedding → DB; **incremental** — unchanged files reused via `source_mtime`/`source_size` fingerprint, `force_reanalyze=True` to override), scan/verify/proxy/structure, shot queries (`get_shots_by_type`, `classify_shot_attributes`), `export_metadata_json` |
| [search_agent.py](app/agents/search_agent.py) | **Retrieval only** — returns candidate filenames + suggestion marker + grounded relevance %, never picks "best" | **`search_catalogue`** (ONE unified tool wrapping `retrieval_service.hybrid_search`: SQL hard filters + vector semantic recall with lexical fallback — LLM just fills structured query params), `list_all_shots` (ground-truth). The old per-attribute SQL tools were merged away. |
| [selection_agent.py](app/agents/selection_agent.py) | Intent-aware **edit-timeline orchestrator** (NOT a score ranker) — chooses a timeline structure that fits the editing intent (NO fixed narrative arc; any number of "Timeline Steps") and explains each step's placement/connection/pacing | `get_candidate_details` (by shot_id OR file path), **`plan_timeline`** (turns the ordered clips + per-clip importance into structured **segments** via [timeline_service](app/services/timeline_service.py): auto-detects a target duration in the intent → **TIMED MODE** trims clips and allocates screen time proportionally to importance, else **FULL CLIP MODE** keeps full lengths; emits a fenced ```json plan the UI/Delivery consume), `generate_delivery_summary`. Consumes the editor's **curated** clips, not raw Search output. |
| [delivery_agent.py](app/agents/delivery_agent.py) | **Project compiler** (NOT an editor) — compiles the edit timeline into a Premiere Pro–importable project file. Preserves clip order + trims exactly; makes no creative/ranking decision | **`compile_timeline_segments`** (preferred — consumes the `plan_timeline` JSON directly, honouring per-segment in/out trims), `compile_premiere_project` (ordered clips → sequential time mapping, full clips), `preview_delivery_timeline` (dry-run). All resolve ordered clips → **FCP7 XML `xmeml` v5** that Premiere imports natively + JSON intermediate, written to `PROCESSED_OUTPUT_DIR/exports`. Tracks: V1 video, A1 original audio, A2 secondary audio only when a clip truly has a 2nd audio stream. Backed by [app/services/premiere_export_service.py](app/services/premiere_export_service.py) (`build_timeline`/`to_fcp7_xml`/`compile_project`; per-clip `in_point`/`out_point` supported). Refuses to compile if any identifier does not resolve to a real catalogued clip — never fabricates a media reference. |

There is no automated quality scoring agent — quality is the editor's judgement, supported by the Selection Agent's explanations. (The `quality_score`, `scene_number`, and `take_number` columns were dropped from `shots` — they were always `NULL` on real ingested rows, so the `filter_low_quality` Selection tool and the scene-based Ingest query tools that depended on them were removed too.)

**Every agent follows the same three-part contract** — when adding or editing an agent, preserve this shape because the orchestrator imports these three names per agent:
- `@tool`-decorated functions + a `ToolNode`,
- `<name>_assistant(state, config)` — binds tools to the LLM, prepends a `SystemMessage` prompt, returns `{"messages": [response]}`,
- `should_continue_<name>(state, config)` — returns `"continue"` if the last message has `tool_calls`, else `"end"`.

### Shared state

[app/models/state.py](app/models/state.py) defines `ProductionState` (a `TypedDict`), the single state object threaded through the entire graph. `messages` uses the `add_messages` reducer; `remaining_steps` (`RemainingSteps`) guards against infinite ReAct loops. Agents communicate by reading/writing fields on this shared state. The `human_approval_gate` fires when `selected_shots` or `recommendations` is non-empty (editorial picks need human sign-off). Add new state fields **additively** to stay backward-compatible.

### Services (shared singletons)

- [app/services/openai_service.py](app/services/openai_service.py) — exports module-level `llm` (and `llm_fast`), plus embedding helpers `get_embeddings()` / `embed_texts(texts) -> list[list[float]] | None` (`settings.EMBEDDING_MODEL`, returns `None` without a key/on failure — never a fabricated vector). **Import `llm`/`embed_texts` from here**; agents bind tools via `llm.bind_tools(...)`. Don't construct `ChatOpenAI`/`OpenAIEmbeddings` directly in agents.
- [app/services/retrieval_service.py](app/services/retrieval_service.py) — **hybrid retrieval** for the Search stage: `hybrid_search(project_id, *, keywords, shot_type, orientation, people, min_duration, max_duration, top_k)` returns structured candidate dicts (metadata + `relevance` + `group_size` + `suggestion` marker). SQL hard filters → vector cosine (numpy) over stored embeddings → lexical fallback when no embeddings. Both the Search Agent's `search_catalogue` tool **and** the Streamlit curation UI call this directly, so retrieval is identical LLM-driven or user-driven. Also exports `group_size(people_count)`.
- [app/services/database_service.py](app/services/database_service.py) — exports singleton `db` (a LangChain `SQLDatabase`, read path) **and** module-level write helpers `replace_project_shots(project_id, rows)` / `get_catalogued_paths(project_id)` / `get_catalogued_shots(project_id)` over the underlying `_engine` (this is how real ingested rows enter the catalogue). The `shots` schema and demo rows are defined inline (`_SCHEMA_DDL` / `_DEMO_SEED`, built by `_create_engine()`, which persists to `settings.METADATA_DB_PATH` and seeds demo data only when the DB is empty; tests set that path to `:memory:` via `tests/conftest.py`); `shots` carries real-metadata columns (`width/height/orientation/fps/codec/has_audio/scene_count/description/people_count`) plus semantic columns (`camera_motion/lighting/mood/subject_position/embedding`, embedding = JSON float list). `_SHOT_COLUMNS` is the contract for `replace_project_shots` — keep it in sync with the table. Tests assert against the demo seed (5 shots, shot 3 is `close_up`, all demo rows `landscape`) — changing the seed will break tests. The `quality_assessments` table is legacy/unused.
- [app/services/ffmpeg_service.py](app/services/ffmpeg_service.py) — subprocess wrappers: `probe_video_metadata` (dims/orientation/fps/codec/audio/duration, rotation-aware), `detect_scene_count` (FFmpeg scene-change cuts), `extract_sample_frames_b64` (in-memory frames for vision), plus proxy generation, frame extraction, duration probing. All degrade gracefully when FFmpeg/ffprobe is absent.
- [app/services/vision_service.py](app/services/vision_service.py) — `analyze_frames(frames_b64) -> VisionTags | None`: GPT-4o (`settings.VISION_MODEL`) with `.with_structured_output(VisionTags)`. Returns `None` (so the caller leaves fields unclassified) when there's no API key/frames or the call fails — it never fabricates.
- [app/services/timeline_service.py](app/services/timeline_service.py) — the Selection-stage **timeline planner** (pure, no LLM/IO). `parse_target_duration(text)` detects a target length in free text ("15s", "1 min", "2 minutes", "1:30" → seconds, else `None`); `allocate_durations(sources, weights, target)` water-fills the target across clips proportionally to importance, capping each at its real length and redistributing the surplus; `plan_segments(clips, target, weights)` returns the structured plan (`mode` = `timed`/`full`, per-segment `in_point`/`out_point`, order preserved). The Selection Agent's `plan_timeline` tool wraps these.
- [app/services/premiere_export_service.py](app/services/premiere_export_service.py) — the Delivery-stage **compiler** (pure, no LLM). `build_timeline(clips, ...)` maps ordered, resolved clips into a neutral JSON intermediate (frame-accurate sequential in/out + sequence positions; order preserved exactly); `to_fcp7_xml(timeline)` renders it as valid FCP7 `xmeml` v5 (Premiere imports natively) with V1/A1/A2 tracks; `compile_project(...)` combines both and writes `.xml` + `.json` to `PROCESSED_OUTPUT_DIR/exports`. Raises rather than emit a clip without a real `file_path`. The Delivery Agent's tools call these directly.

### Config & logging

- [app/config.py](app/config.py) — loads `.env` once and exposes the typed `settings` singleton. Add new env-backed settings here, not via scattered `os.getenv` calls.
- [app/utils/logger.py](app/utils/logger.py) — use `get_logger("<module>")` everywhere for consistent logging.

### UI

[app/ui/streamlit_app.py](app/ui/streamlit_app.py) is the user-facing layer and the **Human-in-the-Loop control layer**. It presents the pipeline as gated phases — ① Ingest → ② Search → ③ Selection → ④ **Deliver** (curation happens continuously via the sidebar Bin checkboxes) — where everything after Ingest stays disabled until `st.session_state.ingest_done` is set ("Reset Pipeline" clears all session state). Key flow change: **Search calls `retrieval_service.hybrid_search` DIRECTLY** (not through the LLM) and stores structured candidates in `st.session_state.search_candidates`; the **curation layer** renders each candidate as a checkbox + suggestion marker (🟡/⚪/🔴) + metadata preview; the editor checks which clips participate, and only those `selected_candidates` (file paths) are handed to Selection. **Selection invokes the compiled `selection_agent` sub-agent DIRECTLY** (bypassing the supervisor) with the intent + curated clip list; the UI extracts the `plan_timeline` structured plan (fenced ```json) from the returned messages and stashes it in `st.session_state.last_timeline_plan` (+ `last_timeline`/`last_timeline_paths`). **Deliver invokes the compiled `delivery_agent` DIRECTLY**, handing it that structured plan so it calls `compile_timeline_segments` (trims + order preserved) to write the FCP7 XML. The sidebar Bin has a **Select-all** toggle (an `on_change` callback that ticks/unticks the whole pool without fighting manual picks). Each stage renders its **own output inline** (timeline under ③ Selection, export result under ④ Deliver); the running agent transcript is demoted to a **collapsed "🛠️ Debug log"** at the bottom. Ingest and free-text follow-ups still go through `mapo_agent`. It lazy-imports the graphs (to avoid recompiling on every rerun), builds a `config` with `thread_id`/`user_id`, seeds a fresh `ProductionState` per `invoke`, and mutates `settings.RAW_FOOTAGE_DIR` from the sidebar.

## Conventions

- Tool docstrings are the agent's API contract — the LLM selects and fills tools based on them. Write them precisely (args + return description).
- Ingestion is real (ffprobe + FFmpeg scene detection + GPT-4o Vision); PostgreSQL is still the only simulated/aspirational piece.
- **Never fabricate catalogue data.** Tools return real measurements or `None`/`unknown`; agent prompts forbid inventing filenames, scores, or tags. If you add a tool or prompt, preserve this — it's the fix for the agents hallucinating clips that don't exist.
- `pydantic` schemas in [app/models/schemas.py](app/models/schemas.py) define structured shapes (`ShotMetadata`, `VisionTags`, `EditingIntent`, `ClipRecommendation`, `TimelineEntry`/`EditTimeline`, etc.) but agents currently pass plain strings/SQL results through state — the schemas document intended structure and are **not yet enforced end-to-end**.
- Search vs. Selection vs. Delivery is a hard responsibility boundary: Search **retrieves candidates only** (hybrid recall, no "best" pick); Selection **orchestrates the editor's curated clips into an intent-driven edit timeline** — it chooses whatever structure/pacing/length best fits the stated editing intent (NO fixed narrative arc; "Timeline Steps", not mandatory roles) and explains each step, it does not rank by score; Delivery is a **pure compiler** — it turns the finished timeline into an importable Premiere project and **must never re-order, drop, trim, or otherwise edit** clips (order in = order out). Keep retrieval/ranking logic out of Selection, "best take"/timeline logic out of Search, and any creative/ranking logic out of Delivery.
